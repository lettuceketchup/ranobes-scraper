# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-script Python tool that scrapes a novel from ranobes.net and saves it as an `.epub`, optionally including reader comments. Everything lives in `main.py` — there is no package structure and no build/lint tooling (one self-check file, `test_main.py`, covers the pure functions). The script is organized into functions/classes (not one flat top-to-bottom block), but it's still a single file by design.

## Commands

Setup:
```
pip install -r requirements.txt
python -m playwright install chromium   # one-time; downloads the browser main.py drives
```

Run:
```
python main.py
python main.py --help                                    # list every CLI flag
python main.py --url <novel-url> --start 1 --end 20       # skip the matching prompts
python main.py --url <novel-url> --start 1 --end 20 --comments
python main.py --url <novel-url> --start 1 --end 100 --volume-label "Vol. 2"   # series/volume metadata
python -m py_compile main.py                              # quick syntax check
python test_main.py                                       # self-check: cleaning, footnotes, comment cap, cache sweep, epub build + Calibre conversion (TEST_OUT_DIR keeps the output)
./display.sh start|stop|status                            # virtual display + VNC for solving CAPTCHAs on a headless box (phone)
```
Any flag left unset falls back to an `input()` prompt (novel URL, then start/end chapter, then a comments y/N prompt) — the script is still fully interactive by default, matching its original behavior. At the end, after all chapters are fetched, it writes the `.epub` straight into `--output-dir` (default: the project folder) as `<novel title> - Chapters A-B.epub`, adding ` (2)` etc. rather than overwriting an earlier build. `--save-dialog` brings back the old tkinter "Save As" window (hidden always-on-top parent so it can't open behind other windows); it needs a desktop, which is why it is no longer the default.

There is no linter or CI config. `test_main.py` is plain asserts (no framework); its cache sweep and epub build use the pages in `.page_cache/` and skip if it's empty. It does not touch the network or the browser.

## Architecture

`main.py` is built around a handful of pieces that all funnel through one fetch path, rather than being four independent bolted-on features:

1. **`BrowserSession`** (replaces the old bare module-level `playwright`/`browser`/`page` globals). Owns one persistent Playwright/Chromium session and exposes `fetch_soup(url)`. ranobes.net fronts every page with a Cloudflare Turnstile bot check that a plain HTTP client (`urllib`/`requests`) cannot pass — do not reintroduce raw HTTP calls for fetching site pages. The one deliberate exception is `fetch_bytes(url)`, which uses `context.request.get` (still carrying the session's cookies) for static assets like the cover image, which aren't behind the bot check. It bypasses `fetch_with_retry`/`PageCache`, so a failure there only logs a warning and the book is built without a cover. `switch_to_headed(url)` / `switch_to_headless()` swap the entire browser between headless and a visible window while carrying `storage_state()` (cookies) across the swap — used for the anti-flood hand-off below. **Cookies persist across runs**: `state_path` (`--session-file`, default `.browser_state.json`, gitignored, written atomically with mode 600) is loaded at startup (unless `--fresh-session`; a corrupt file is ignored with a warning) and saved by `save_state()` after a CAPTCHA is cleared and in `close()`. `_snapshot()` keeps the last good `storage_state()` in `_last_state`, so a browser swap still has cookies to carry even if the window was closed by hand. A headed launch is maximized with `no_viewport=True` so the challenge fills the VNC screen. `switch_to_headed` raises only when the window can't launch; a failed navigation is *returned* as a message (the window is up, the human can reload). `safe_page_content()` retries `page.content()` a few times if it's called mid-navigation (e.g. right after a Turnstile challenge auto-redirects on success), which otherwise raises instead of returning content.

2. **`PageCache`**. Caches fetched pages on disk under `.page_cache/` (default; `--cache-dir` to relocate, `--no-cache` to disable), keyed by a SHA-256 hash of the URL. **Only ever written to from `fetch_with_retry`, never from `BrowserSession.fetch_soup` directly** — a page is cached *after* `is_anti_flood_blocked()` has confirmed it's real content, so a CAPTCHA/challenge page can never get cached and served back later as if it were the real page. `set()` self-heals if the cache directory goes missing mid-run (e.g. deleted externally) by recreating it and retrying once, rather than silently going dark for the rest of the process — this was a real bug once (an unrelated `.page_cache` deleted while a run was live silently disabled caching for the remainder of that run).

3. **`fetch_with_retry(session, url, args, *, label, progress_bar=None)`**. The single fetch path used everywhere — novel page, each chapter-index page, each chapter page, and comment-pagination follow-ups. On each call: checks the cache first; on a miss, fetches via `BrowserSession.fetch_soup`; classifies any exception into a human-readable message (`classify_exception` — no internet, DNS failure, connection refused/timed out, or a generic fallback) and retries up to `--retries` times with `--retry-delay` between attempts; if the fetched page is itself a Turnstile/CAPTCHA challenge (`is_anti_flood_blocked`), hands off to `handle_anti_flood` (opens a *visible* browser window reusing the same session's cookies — solving it in an unrelated browser wouldn't clear the Playwright session's block — then resumes) without burning a retry attempt. **Once `--retries` is exhausted, it never auto-skips or auto-aborts** — `prompt_human_intervention` stops and asks a human to retry/skip/abort. `safe_input()` degrades `input()` to `None` instead of crashing if stdin is ever unavailable (e.g. non-interactive invocation), treated as an abort.

4. **Comment extraction** (`extract_comments`, `_extract_comment_list`, `_sanitize_node`, `render_comments_html`, `build_comments_section`; opt-in via `--comments`, off by default). Recursively parses `#dle-comments-list > ol.comments-tree-list` (nested `<li class="comments-tree-item">` / `<ol class="comments-tree-list">` for replies, arbitrary depth) into `CommentNode`s — author, ISO timestamp, reply-to, up/downvotes, and a sanitized body (safe subset only: text, `<br>`, and quote blocks; links/images/other tags are dropped since comment bodies are untrusted user content). Rendered with classes from the shared stylesheet (`BOOK_CSS`) and a depth-capped indent (`MAX_COMMENT_INDENT_DEPTH`), appended after the chapter text in the same `EpubHtml` item. `limit_comments` (`--max-comments N`, default 20, `0` = no cap) keeps the best-voted threads (ranked by summed net votes, ties in site order) until N comments including replies are used, trims the last thread to fit, restores site order, and `build_comments_section` adds "N more comments not shown". A chapter with no comments gets no Comments section at all. This novel averages ~3.6 comments per chapter, so the cap rarely bites here. **Extraction must run on `site_soup` before `#dle-comments-list` is decomposed** in the main chapter loop — the reply-to marker and online-status spans it depends on live inside it. The decompose itself is unconditional, even when `--comments` is off, so nothing from the comments tree can be mistaken for story text. (Spans are no longer stripped from the page: chapter text is read only from `#arrticle`, and none of the cached chapters has a span inside a story paragraph.)

   `extract_comments_with_pagination` follows `.dle-comments-navigation` "next" links (capped by `COMMENT_PAGE_SAFETY_CAP`), but no real chapter with paginated comments has been seen yet, so that path is untested against the live site.

4b. **Chapter discovery and book metadata** (inline in `main()` plus `extract_novel_metadata`, `apply_book_metadata`, `apply_series_metadata`, `_cover_bytes_to_jpeg`, `build_intro_html`). The chapter count comes from the novel page. The chapter-index URL comes from the `a.uppercase.bold` "Start reading" link, and its pages (`.../page/N/`, 25 chapters per page) each embed a JSON-ish `"chapters":[...]` blob inside a `<script>` in `#dle-content`. That blob is split by hand and parsed with `ast.literal_eval`, then the list is reversed into reading order. If the site changes that script format, this is the code that breaks. Metadata (title, authors, translators, publishers, genres, year, synopsis, `og:image` cover) is read from `.r-fullstory-spec`, `#mc-fs-genre`, and `.moreless__full` and written as Dublin Core/EPUB3 metadata. The book identifier is `ranobes-<novel id>`, taken from the URL. Choices made for Kindle that should be kept: the cover is always re-encoded to JPEG (Kindle doesn't render the site's `.webp`); `--volume-label` adds both EPUB3 `belongs-to-collection` and `calibre:series`/`series_index` meta, because calibre series is what makes volumes group together on a Kindle; the intro is a Calibre-style "jacket" page (a facts table plus the synopsis) rather than the site's raw description markup. **Chapter text** is built by `build_chapter_content` (pure function, tested in `test_main.py`) from the `<p>`/`<hr>` children of `#arrticle`:
- Kept inline: `<em>`, `<strong>`, `<br/>` (thoughts, sound effects and system lines were being flattened to plain text before). Everything else (ads, scripts, iframes) is dropped; their text is kept.
- Removed: Discord invite lines and `Join our discord at`, the `◈ <novel title>` banner, and the site's own `Chapter N` echo near the top (the heading already says it). **Matched on the whole paragraph's shape, never on the word "discord"** — chapter 485's translator note says "props to everyone in the discord" and must survive. `Translator:`, `Editor:` and `WeTried Translations` lines are deliberately kept (the user likes them).
- Empty paragraphs are dropped. `* * *`, runs of `─ — = ~`, and `<hr>` all become one centered `<p class="scene">* * *</p>`; consecutive breaks collapse and none is left at the start or end.
- Footnotes: a trailing `Footnotes:` paragraph followed by `[n] ...` paragraphs becomes `<aside epub:type="footnote">`, and a matching `[n]` in the body becomes a `noteref` link (Kindle popup). Markers with no matching footnote are left alone; a footnote with no marker in the text (6 of 134 in the cache) just shows at the chapter end. The site's template also leaves an empty `Footnotes:` heading, or a stub `[1]` with no text, on chapters that have no footnotes (e.g. 5, 242, 244); `_split_footnotes` consumes and drops those. The footnote anchors carry element `id`s, and ebooklib turns every `id` into a hidden `page-list` of fake page numbers in `nav.xhtml` (which Kindle can show as real page labels), so `finalize_and_save` writes with `{"epub3_pages": False}`; `test_main.py` checks the nav has no `page-list`.
- Title: the heading is `Chapter N` from the `<h1>` (the novel name is glued onto it once spans are stripped, and the site has no real chapter titles). Non-chapter pages keep the text before the `|`, e.g. the translators' `Announcement` page, which sits in the chapter index and is included.
- Styling is one shared `style/book.css` (`BOOK_CSS`): no `font-family`, no `line-height`, so Kindle's own font/size/spacing settings apply. The old per-paragraph Google Fonts `<link>` and `Nunito Sans` inline styles are gone.

**Run summary:** after the chapter loop `main()` logs chapters fetched vs requested, an approximate word count, lines removed, skipped chapters, non-chapter pages, and any missing or duplicated chapter numbers. `--end` is clamped to what the index lists. Exit code: 0 success, 1 aborted/failed, 130 Ctrl+C.

**Ctrl+C (important, learned the hard way):** never let a `KeyboardInterrupt` fire *inside* a Playwright sync call. It leaves Playwright's event loop half-finished, so the next Playwright call (`storage_state()` while saving cookies in `close()`) hangs, and further Ctrl+C presses only add "Task was destroyed but it is pending" noise (seen on Windows, 2026-11-21, after chapter 20 of a full run). So `main()` installs a SIGINT handler (`install_sigint_handler`): the first Ctrl+C sets `_stop_requested`, and `check_stop()` (top of the index loop, the chapter loop, every `fetch_with_retry` attempt, `wait_for_captcha_cleared`) raises `KeyboardInterrupt` at a safe point, which the existing `except KeyboardInterrupt` turns into the partial-save offer; a second Ctrl+C `os._exit(130)`s immediately. Sleeps in the fetch path use `stoppable_sleep`. At any `input()` prompt (`ask()` / `safe_input`) the default handler is restored (`interruptible`), because nothing is in flight there and Ctrl+C must still end the prompt. Verified with a real SIGINT mid-fetch: stopped in ~2 s, saved the partial epub, exit 130, no Playwright errors. Don't call Playwright from a `finally` that can run after an interrupt raised inside Playwright, and don't add new `time.sleep`s or bare `input()`s to the fetch path.

5. **CLI / interactive prompts** (`parse_args`, `resolve_interactive`, `resolve_chapter_range`). `argparse`-based, `-h`/`--help` documents every flag. Anything left unset on the command line falls back to the original `input()` prompt — see Commands above.

6. **Assembly + save** (`build_output_filename`, `finalize_and_save`, `offer_partial_save`). Filename is derived from the novel title and the actual chapter numbers present in `chapter_epub` (not `--start`/`--end`, since a partial/aborted run may not match), sanitized for filesystem-invalid characters. The save dialog opens in `--output-dir` (defaults to the project directory) pre-filled with that name — `write_epub` is called on the dialog's full path directly rather than `os.chdir`-ing into the target directory (the old code did this, which had the side effect of permanently changing the process's working directory). If the run stops early — a human chooses "abort" after exhausted retries, gives up on an anti-flood block, or Ctrl+C — `offer_partial_save` is always given a chance to build the `.epub` from whatever chapters were already fetched rather than discarding that work; it only skips the prompt if nothing was fetched yet.

7. **`main()`** ties the above together and wraps the whole run in `try/except RunAborted/except KeyboardInterrupt/finally: session.close()` so the Chromium subprocess is always cleaned up, including on an aborted/interrupted run.

**Retry/failure behavior (changed from the original script):** every fetch goes through `fetch_with_retry`, which caps retries at `--retries` (default 5) with `--retry-delay` (default 15s) between attempts, then always escalates to a human decision (retry/skip/abort) rather than looping forever or silently giving up. `--request-delay` adds an optional pacing delay between successive fetches to proactively avoid triggering anti-flood in the first place.

**Anti-flood / CAPTCHA handling:** `is_anti_flood_blocked()` detects both the JS Turnstile challenge and further-escalated interactive CAPTCHAs by checking for known challenge-page selectors (`.cf-turnstile`, a `challenges.cloudflare.com` iframe, generic captcha selectors) and title/body text markers (`CAPTCHA_MARKERS`). When triggered, `handle_anti_flood` pops a real visible browser window (same session, same cookies), calls `notify()` (terminal bell + `termux-notification` if on PATH; `--no-notify` to disable), and `wait_for_captcha_cleared` polls `captcha_page_state` every `CAPTCHA_POLL_SECONDS` via `select` on stdin: it resumes by itself after `CAPTCHA_CLEAR_CHECKS` clear reads in a row (Enter checks immediately and resumes on one clear read; `abort`, closed stdin, a closed window, or `--captcha-timeout` raise `RunAborted`). `captcha_page_state` reads the URL with `page.evaluate("location.href")`, not `page.url` — after a failed `goto()`, Playwright's `page.url` stays `about:blank` even once the human reloads the real page. Subprocess calls for notifications use `DEVNULL`, not captured pipes, so a lingering Termux:API helper can't defeat the timeout.

**Display for CAPTCHAs on a headless box:** `display.sh start|stop|status` runs TigerVNC `Xvnc :1` (X server + VNC in one, 127.0.0.1:5901 only, no password) + openbox in a tmux session named `display`. Xvfb + x11vnc was tried first and abandoned: under proot, x11vnc accepted TCP connections but never sent the RFB handshake, so viewers hung at "connecting". Killing the tmux session doesn't reliably end its programs under proot, so `stop` also `pkill -x`es them by exact name. `ensure_display()` sets `DISPLAY=:1` at startup if it's unset and `/tmp/.X11-unix/X1` exists, and otherwise logs a heads-up. On the phone this is viewed in the AVNC app (gesture style "Touchscreen" for drag puzzles). If chapters start failing repeatedly in a burst even after this, that's still a sign to slow down (`--request-delay`, lower `--retries`) rather than retry harder.

**Headless runs can be blocked outright:** the old assumption that a headless browser always clears the bot check on its own is no longer reliable. On 2026-11-14, a run from the Termux/proot phone got ranobes' own image CAPTCHA ("If you are human, click on the similar image") on the very first request (the novel page). It never cleared in 30s of polling, with either Playwright's default headless shell or full Chromium (`channel="chromium"`). So a human-solvable visible window is effectively required. When the visible browser can't launch (no display), `switch_to_headed` restores the headless browser and re-raises, and `handle_anti_flood` turns that into `RunAborted` with a clear message from `headed_launch_failure_message()`. That way the partial-save offer still runs and there's no traceback.

**Known gotcha for future edits:** `PageCache` writes are gated on `is_anti_flood_blocked()` returning `False` — never move a cache write earlier in the fetch path (e.g. into `BrowserSession.fetch_soup`) without preserving that gate, or a challenge page can get cached and served back as if it were real content on a later run.

**Unused imports:** `shutil`, `zipfile`, and `pdfkit` are imported in `main.py` and listed in `requirements.txt` but not currently called anywhere in the script (the README mentions optional PDF conversion, but that path isn't implemented).
